# Cube Cube Cube

A small collection of relaxing browser puzzles, built with Three.js, vanilla JavaScript, and Vite. The home page offers 42 original illustrated games, including flower deductions, picture logic, lantern toggles, the 3D cube, picture puzzles, an ant colony and thirty-six other little escapes. No account, advertising, timers or paid hints.

## Publishing

GitHub Pages serves the production build. Pull requests run the puzzle tests, Chromium gameplay tests and production build without deploying. Every push to `main` runs those checks, then deploys the game through `.github/workflows/pages.yml`. The workflow supplies the repository base path to Vite, so assets and the home link work under `/CubeCubeCube/`. It can also be run manually from GitHub Actions.

## Releases and changelog

Record notable changes in the `Unreleased` section of `CHANGELOG.md`, under the relevant Keep a Changelog headings. For a release:

1. Update the version in `package.json` and `package-lock.json` together, for example with `npm version 0.2.0 --no-git-tag-version`.
2. Move the pending notes into a dated `## [0.2.0] - YYYY-MM-DD` section and update the comparison links.
3. Commit and push the changes to `main`, then wait for its checks to pass.
4. Create and push an annotated matching tag: `git tag -a v0.2.0 -m "Cube Cube Cube v0.2.0"`, then `git push origin v0.2.0`.

The `Publish release` workflow validates the tag, package versions, dated changelog entry, and membership in `main`. It runs the tests, builds a portable static website, and creates a GitHub release using the matching changelog notes. The release includes a `CubeCubeCube-vX.Y.Z-web.zip` archive; source archives are also provided by GitHub. Prerelease versions such as `v0.2.0-beta.1` are marked as prereleases automatically. Existing tags are never moved.

## Play locally

Requires Node.js 20.19+ or 22.12+ (tested with Node 24).

```powershell
npm install
npm run dev
```

Open **http://127.0.0.1:5173** and choose a game from the home cards. The cube is at `cube.html`; its existing progress remains intact. Its first 28 puzzles introduce the rules, mechanics, and shapes. Puzzle 29 begins a virtually unlimited generated journey. Choose **The collection** to browse opening puzzles by family, start or resume the journey, browse pages, or jump to a puzzle number. Finishing a puzzle always leads to the next one.

## Endless progression

Each numbered puzzle is generated from a stable seed: restart, undo, and reload preserve its identity. Difficulty tiers advance every eight generated puzzles. The curve adds larger boards, more arrows, longer paths, more forks, more colored connections, and a stronger preference for blocking dependencies. Cubes, prisms, tunnels, and integrated terraces alternate along the journey.

Boards grow from 7 to 10 cells per side; density and path length also have practical limits to keep the game readable and responsive. Later tiers continue varying layouts and biasing generation toward deeper dependencies. Difficulty varies between individual shapes while the overall curve rises.

Families cover foundations, connections, parking, branches, tunnels, terraces, deflection, rotation, and mixed mechanics. Endless tiers introduce pressure buttons at tier 2, fixed deflectors at tier 3, alternating deflectors at tier 4, rotating crowns at tier 5, and mixed pressure/deflection on terraces at tier 6. Stateful pockets reserve their surface and exit corridors so the surrounding filler cannot break their solutions.

Arrows are built in reverse solution order: their exit routes must be clear of all earlier arrows, both routes for a fork, and solid geometry. Several seeded candidates are compared for dependency depth and opening choices. Circle levels draw from 38 audited dependency layouts with three to five arrows, several stops, opposite-head choices, and coordinated forks. Early groups need at least three parking moves; later groups require four, five, then seven. Circle challenges continue appearing on unequal-face boards throughout the journey.

Parking groups reserve their surface so filler cannot break their solutions. Hints search each small group independently, then solve the surrounding arrows, avoiding an expensive search of the entire board. Choosing another head or parking order can block a solution: undo remains available, and hints explicitly explain when a step must be undone.

Generation retries and a deterministic density fallback handle crowded seeds. Only a small cache of generated boards and a page of collection cards are kept in memory. Completed endless puzzles are stored as merged number ranges, so thousands of consecutive completions occupy a few bytes rather than thousands of save entries.

## Rules and controls

- Drag the cube to inspect all six sides with unrestricted trackball rotation, including upside-down views. Scroll or pinch to zoom; the small rotation button restores the starting view.
- Tap any part of an arrow. It can leave if no other arrow lies between its head and the edge of that face in its pointing direction.
- Its tail follows its winding path, including around cube edges, before flying away.
- A blocked arrow briefly turns red and highlights its blocker. Attempts are unlimited.
- Colored ridges redirect an arrow onto the neighboring face. Movement continues across painted edges until an ordinary edge or a pause circle; blockers are checked on every face along that route. A completely closed route cannot leave the board.
- Opposite-ended two-headed arrows move toward the head you tap. Forks count as one arrow and move both heads along their own routes simultaneously. Both routes must be clear, whichever head or part of the body you tap.
- A small circle pauses an arrow when its head reaches it. Its new body position changes which arrows it blocks; tap again to resume. Level 17 requires parking an arrow to break a dependency cycle.
- A pressure button also pauses a head. It holds gates of the same color open while the head stays there; its gates close as soon as that head departs. A departing head cannot use its own released gate.
- Every arrow and either live fork head can operate a button. Mechanism levels briefly lock all arrow input during movement, then unlock when it finishes. If an animation fails, the committed final state is restored and play continues.
- Blue bent tiles turn a passing head 90 degrees left or right. Striped purple tiles do the same, then reverse their turn for the next head. A blocked move never changes a deflector. These tiles are operated by arrows, with no direct tile controls.
- Parking a head on a blue spiral turns the upper section 90 degrees around the vertical axis. Its arrows, tiles, and colored ridges rotate with it. Arrows spanning the moving seam prevent rotation until cleared. The first rotating shape uses a square crown above a fixed base, so all four orientations preserve the solid geometry.
- Later boards include rectangular prisms, a tunnel through a solid, and a larger solid with a stepped section cut into one corner. Arrows use the exposed surface, including inner walls, treads, and risers. An exit must clear the solid itself; generated arrows cannot fly into a tunnel wall or another part of the shape.
- An ordinary exit still checks its flight against other arrows. An arrow across a hole on the same face blocks it, while a visually overlapping arrow at another depth does not.
- Clear every arrow to finish the level. Undo, hints, and restart are always available.
- Keyboard: **arrow keys** rotate; **H** highlights a removable arrow and turns the camera toward it; **Enter** releases the highlighted arrow; **U** undoes; **R** restarts.
- Sound is optional. Choose from Warm ivory, Garden mint, and Quiet dusk palettes.

Current puzzle progress, undo history, completed puzzles, journey position, sound, and palette preferences are saved in browser local storage. Saved moves include the chosen head and circle parking, so reloading restores the moved board and undo history. Original saves are migrated automatically. Only the active puzzle's partial progress is retained when switching levels. Completed level badges remain earned if you replay or undo. Clearing browser storage resets progress.

Save format 4 also replays button parking, alternating turns, and section rotations. Earlier endless indices and completion ranges shift by five to make room for the new lessons. An existing endless session retains the previous mechanic generation until the player starts another puzzle; all movement uses the corrected collision rules.

Generator 3 adds the richer circle layouts. Saves from generators 1 and 2 keep the active puzzle and its move history intact, including after restart. Starting another numbered puzzle uses generator 3.

## Verification

```powershell
npm test
npm run test:browser
# Optional complete browser regression suite:
npm run test:browser:all
npm run build
```

Local browser tests use an installed Microsoft Edge. CI uses Playwright-managed Chromium, installed with `npx playwright install --with-deps chromium`.

The default browser suite checks every campaign with one real hint action, exact reload and undo, plus shared controls and physics regressions (`@core`) and detailed scenarios for the latest additions (`@current`). Earlier full completion and repeated responsive tours remain available in `test:browser:all`; use it when a broad UI change needs that coverage. Move `@current` to each new batch rather than accumulating every old tour in CI. Rule tests sample eight boards per 48-level campaign; exhaustive replays are opt-in with `test:levels:all`.

The tests verify representative opening solutions and generated samples across early, late, billionth, and safe-integer-limit puzzle numbers. They check surface topology, arrow and branch connectivity, solid exits and gap-flight collisions, obstruction rules, circle and button parking, gate closure, deflector transactions, moving sections and seams, difficulty progression, undo, compact completion ranges, save replay, actual mouse picking, rotation, complete keyboard play, endless continuation, family filtering, collection paging, dialogs, preferences, and desktop/mobile layouts. The production bundle is generated in `dist/`; use `npm run preview` to serve it locally.

- `src/pocket-main.js`, `src/pocket-style.css`: shared shell for Atelier, Bobines, and Escapade, with chapter collections, controls, optional audio, progress, and independent saves.
- `src/pocket-core.js`: deterministic helpers, transactional undo, bounded solution search and validated save replay.
- `src/atelier-puzzle.js`, `src/bobines-puzzle.js`, `src/escapade-puzzle.js`: separate discrete rules and guaranteed-solution construction for 48 levels per game.
- `src/atelier-scene.js`: Three.js stacked assemblies, occlusion-aware screw picking, orbit controls, unscrewing and departing plate animation.
- `src/pocket-canvas.js`, `src/pocket-previews.js`: original thread and creature rendering, touch picking, winding/exit animation and home illustrations.
- `src/suite-main.js`, `src/suite-style.css`, `src/suite-canvas.js`, `src/suite-previews.js`: the next four games' shared interface, Canvas scenes, animations, touch picking and illustrated home cards.
- `src/passages-puzzle.js`, `src/voyage-puzzle.js`, `src/carrousel-puzzle.js`, `src/broderie-puzzle.js`: independent rule models and audited generators for another 192 puzzles.
- `src/picture-art.js`: sampling the project's original collection illustrations and computing outside-connected pixel accessibility.
- `src/colony-puzzle.js`: outside-space reachability, color quotas, guaranteed-solution level construction, five-slot simulation, hints, undo, and validated saves.
- `src/colony-scene.js`: Three.js pixel cubes, original ant meshes, path-following pickup/return animation, and a garden tray.
- `src/colony-main.js`, `src/colony-style.css`: Colony controls, queues, collection, responsive layouts, and independent local-storage progress.
- `src/puzzle.js`: discrete surface topology for cubes and voxel solids, branching arrows, movement rules, seeded level generation, solution search, and game state. No Three.js or DOM dependencies.
- `src/mechanics.js`: pressure occupancy, gates, fixed and alternating turns, rigid section rotation, transactional movement, stateful solution search, and mechanic lesson layouts.
- `src/parking.js`: audited circle dependency patterns, tier selection, and seeded surface placement.
- `src/scene.js`: rounded cube, arrow meshes, occlusion-aware picking, free trackball controls, quaternion camera transitions, and path-following animations.
- `src/main.js`: interface, input, sound, preferences, and progress orchestration.
- `src/storage.js`: versioned browser save format, validation, and graceful handling of unavailable storage.
- `src/style.css`: desktop and touch layouts, dialogs, and reduced-motion support.

The opening puzzle and mechanic tutorials are handcrafted. Larger boards use fixed, audited seeds. Generation constructs arrows in reverse removal order, so every selected board has a complete solution. On boards without circles, picking any removable arrow cannot introduce a deadlock because removal only clears occupied cells. Circle puzzles can change occupancy; hints search board states to find the next move in a complete solution.

## Picture puzzles (2D)

Open `image.html`, or choose **Picture puzzles** from the cube game. A sample landscape is playable immediately. Upload a photo or screenshot, drop an image, paste with Ctrl+V / Command+V, or use the clipboard button. Direct image links work when the source allows CORS; webpage links require uploading a screenshot for this first version. There is no screenshot backend.

Drag in the preview to select a crop, or choose Whole image, Square, Portrait, or Wide. Choose Gentle, Thoughtful, or Tangled difficulty and Soft, Balanced, or Fine detail, then **Create puzzle**. **Try different paths** makes a fresh seeded arrangement of the same image. Restart keeps the current arrangement. All image processing and puzzle generation run locally; uploads are never sent to a server.

The flat generator partitions visible image cells in removal order, growing tails into the remaining image while each new head has a clear exit. Every arrow spans at least five cells; target lengths are longer to reduce repetitive clicking. Short fragments join existing tails or body detours when that preserves a clear solution; fragments that cannot join stay empty. Crops too fragmented to form any long arrow show a message asking for a larger visible area or more detail. The construction order proves solvability, and any available removal keeps the puzzle solvable. Paths favour neighbouring colours and avoid strong colour boundaries. Each body segment and head samples the corresponding image pixels, retaining those colours during departure. Partial transparency is composited against white; fully transparent cells are left empty. Uploaded sources are resized to at most 1200 pixels on their longest edge and saved losslessly. Grid resolution follows the crop's aspect ratio, with a 72-cell limit per axis and a minimum of four cells for very thin crops. Saved boards with shorter arrows regenerate once, retaining the source, crop, and settings and resetting that board's move history.

Tap an arrow to release it. Blocked paths are outlined, and **H** highlights a clear arrow; **Enter** releases the hint, **U** undoes, and **R** restarts. Scroll or pinch to zoom, drag to pan, and use **Fit** to centre the board. **Original** shows the cropped source image for comparison. Images, exact generated boards, and move history are saved in IndexedDB separately from the cube's local-storage progress. Invalid saves fall back to a fresh sample puzzle. File imports are limited to 15 MB and 40 megapixels.

The picture page uses Canvas 2D and a small module Worker, and does not load Three.js. Its modules are `src/image-puzzle.js` (rules and generation), `src/image-scene.js` (rendering and picking), `src/image-main.js` (import/crop and UI), `src/image-worker.js` (generation), and `src/image-storage.js` (local persistence). Both HTML entry points are included in GitHub Pages and release builds.

The game implements the described mechanics with its own branding, art, and levels. It does not reproduce CubeAway's complete level catalog or special power-ups. WebGL is required; all assets and dependencies are served locally, with no CDN requests.

## Colony (3D)

Open `colony.html`, choose **Colony** from either game's navigation, or use its home card. This original implementation takes inspiration from [Colony Flow's color-box and ant collection mechanics](https://play.google.com/store/apps/details?id=com.abi.colony.flow). The artwork, levels, interface and models are created for this project.

Select the top box of one of four queues. It occupies one of five active slots and sends a worker to every accessible matching cube, up to its remaining quota; there is no fixed worker cap. Only cubes adjacent to outside-connected empty space are accessible; enclosed holes remain blocked. Workers follow those empty corridors, remove a cube on arrival and carry it back. Newly exposed matching cubes receive workers on the next simulation update. The box counter decreases on delivery, and a filled box releases its slot. Boxes whose color is still buried wait. Five waiting boxes cause a deadlock; undo is always available. Shared instanced meshes render large swarms with fourteen ant-part draws instead of one mesh per worker part.

Twenty-four original pictures include the first six motifs plus a butterfly, fish, bee, cup, strawberry, sailboat, castle, cat, owl, cactus, turtle, balloon, snowflake, crab, bird, lighthouse, cherries and planet. The 96-puzzle opening journey introduces five chapters: Découverte (1–6), Malin (7–24), Corsé (25–48), Difficile (49–72) and Expert (73 onward). Boards grow from 16×16 to 24×24. Nested rings, repeated colors and quotas that span buried regions require teams to wait for other colors; the audited route can coordinate four occupied slots on expert boards. Every reserve is constructed through an actual complete simulation, with exact color totals and at least one legal solution. Later numbered boards use seeded reserve arrangements, mirrored art and expert accents. Collection paging and chapter buttons let players explore twelve puzzles at a time; the number field supports puzzle 1,000,000.

Use **Un petit indice** for a move verified by a bounded state search, **Annuler** to restore the complete previous state, and **Recommencer** to reset the same puzzle. Pause and ×2 change the animation pace. H asks for a hint, Enter sends the indicated box, U undoes, R restarts, 1–4 choose a queue, and Space pauses when the canvas is focused. Dialogs and hidden tabs suspend simulation.

Colony uses its own versioned local-storage key. Saves include the generator version, queue positions, active boxes, trips in progress, undo states, completed puzzles and speed. Older saves retain their exact original board and undo history, including after restart. Starting another puzzle uses the new generator. Invalid saves fall back to the first puzzle. Storage failures do not prevent playing. Cube and picture progress remain independent. The static build includes `index.html`, `cube.html`, `image.html` and `colony.html`, with links compatible with the configured GitHub Pages base path.

## Atelier, Bobines and Escapade

The three new games have **48 distinct, deterministic puzzles each**, split into four chapters of twelve. All chapters are directly accessible from the collection. Each board is constructed with a complete legal solution; automated tests replay representative solutions at chapter boundaries and verify that difficulty grows through larger assemblies, deeper thread lines, more colors, larger gardens and longer creatures. They are original implementations inspired respectively by [Screwdom 3D](https://play.google.com/store/apps/details?id=com.ig.screwdom), [Knit Out](https://play.google.com/store/apps/details?id=com.sbg.knitout) and [Gecko Out](https://play.google.com/store/apps/details?id=com.dalakgames.slitherrush), with original names, graphics, layouts and levels.

- **Atelier (`atelier.html`)**: remove the exposed screws from stacked 3D plates. Each plate has three screws; removing them reveals the plate below. Two active boxes collect three screws of their color and advance through a visible reserve. Unmatched screws wait in four or five buffer positions. Waiting screws automatically enter a compatible box as it appears. A move exceeding the buffer capacity is rejected without changing the board. Drag to orbit, scroll to zoom, or use the accessible screw buttons. Assemblies grow from two short stacks to three larger stacks.
- **Bobines (`bobines.html`)**: launch the first bobbin in one of four queues into one of three active slots. It winds accessible knots of its color from the tops of the thread lines, up to its quota. Newly exposed matching knots are wound too. A bobbin whose color is buried waits; filling all three slots with waiting bobbins blocks further launches. Full bobbins release their slots. The generator simulates a complete peeling order, gives each bobbin an exact quota and distributes that proven order across the queues. Boards grow from three short thread lines to six deeper lines and six colors.
- **Escapade (`escapade.html`)**: select a creature's head or tail and drag it through adjacent cells, or click an end then a neighboring cell. The body follows. Reach the matching boundary hole to remove that creature; hedges, other creatures, and other colors' holes block movement. The departing tail cell may be entered on the same move. Click a creature button to select its head; the end-switch button selects its tail. Arrow keys and direction buttons also work. Gardens grow from 6×6 with three creatures to 9×9 with six. Construction grows paths outward from reserved exits, places non-overlapping bodies, then audits the reverse order for a complete route.

All three support **H** for a hint, **Enter** to execute it, **U** to undo, and **R** to restart. Bobines also accepts **1–4** for the queue. Sounds are optional. There are no timers, lives, ads or paid tools. Hints first reuse the proven route when possible; otherwise they search the current board within a bounded budget and only highlight a move when a full remaining solution is verified. When that search finds no complete route, the hint offers undo instead of an unverified move. This does not claim that the current position is mathematically impossible.

Each game has its own `cubecubecube-<game>-v1` local-storage key, holding the generator version, current level, replayable move history, completion badges and audio setting. Reload restores both the exact board and undo; restart retains the same level. Invalid saves fall back to puzzle 1. Storage failure does not prevent play. Completion badges survive replay and undo. Saves stay local to this browser.

All twenty-two HTML entry points (home plus twenty-one games) are included in the Vite production build and portable release archive. The Canvas games do not load Three.js; Atelier loads its 3D renderer dynamically. Tests cover representative construction routes, collisions, waiting slots, save corruption, replay, undo, actual pointer play, complete first-level play, collection chapters, reload and 1440px/390px/320px layouts.

## Passages, Voyage, Carrousel and Broderie

Four further games add **48 distinct puzzles each** in the same four chapter collections. Along with the first trio, these seven additions contain **336 audited puzzles**. Saves and completion badges remain separate for every game.

- **Passages (`passages.html`)**, inspired by [Color Block Jam](https://play.google.com/store/apps/details?id=com.GybeGames.ColorBlockJam): slide rectangular blocks in the garden toward their own matching boundary doors. The whole block must fit the opening. Neighbors, hedges and closed boundaries block movement. Choose a block in the scene or sidebar, then drag or use arrows/direction buttons. Construction starts at valid exits, walks each new rectangle through currently free space, then records the reverse placement order as a full solution. Boards grow from three blocks on 6×6 gardens to six larger blocks on 8×8 gardens. Hints search actual rectangle placements and verify that all remaining blocks can exit; if no full route is found, they offer undo.
- **Voyage (`voyage.html`)**, inspired by [Bus Jam](https://play.google.com/store/apps/details?id=com.nt.games.busjam): pick travelers who can reach the bottom platform through empty corridors. The current bus takes its own color; other travelers wait on a five-seat bench. Full buses depart, and waiting travelers automatically board subsequent matching buses. Upcoming color tickets and exact capacities are visible. Each reserve is colored using an actual outside-accessible removal sequence, so every passenger has a boarding route and every color total matches the buses exactly. Larger chapters add longer halls, larger passenger groups, more colors and furniture that shapes the paths.
- **Carrousel (`carrousel.html`)**, inspired by [Pixel Flow!](https://play.google.com/store/apps/details?id=com.loomgames.pixelflow): launch a small shooter from the first position of one of four queues. A discrete lap removes outside-accessible pixels of that color, up to its ammunition and the per-lap shot limit. A shooter with ammunition left returns to one of five waiting slots; click it to send it on another lap once its targets are exposed. A full reserve blocks new launches. Fruitless waiting-shooter relaunches are rejected without changing progress. Pixel and ammunition totals are conserved by color, and every reserve has a complete route including relaunches. Images grow from 10×10 to 16×16, using the project's own original art.
- **Broderie (`broderie.html`)**, inspired by [Thread Jam](https://play.google.com/store/apps/details?id=com.sewing.jam): take exposed spools from a layered pile into a seven-slot workbench. Three spools of one color stitch an exact section of the picture and release their three slots. Covered spools remain unavailable until upper layers are removed. Picture sections form a disjoint partition of every pixel, with one triple per section. Construction colors an audited top-down removal route in triples, guaranteeing a complete arrangement without paid tools. Chapters grow from 24 to 57 spools and deeper piles. Original collection pictures appear as animated cross-stitch illustrations.

All four accept **H**, **Enter**, **U** and **R** for hint, execute hint, undo and restart. Carrousel also accepts **1–4** for launch queues; Passages accepts arrow keys. They share the same optional sound, reduced-motion support, exact move-replay saves, chapter collection and local progress behavior as the first trio. Tests replay representative levels added solutions, check collisions and outside reachability, conserve passengers/ammunition/stitch patches, reject corrupted saves, and verify actual mouse/touch-sized layouts and complete browser gameplay.

## Alvéoles, Potions and Liaisons

Three more independent games provide **48 distinct, deterministic levels each** and four directly accessible chapters. Along with the previous seven additions, they contain **480 audited puzzles**. They use the same independent replay saves, optional sound, undo, restart, completion badges and verified hints.

- **Alvéoles (`alveoles.html`)**, inspired by [Hexa Sort](https://play.google.com/store/apps/details?id=com.gamebrain.hexasort): choose the head stack of one of three queues, then place it on an empty hexagonal cell. Connected matching top runs gather onto the newly placed stack. Groups of six disappear, potentially revealing further matching layers and causing a cascade. Covered layers remain on their own cells. Use all queued stacks and empty the board. The generator reserves connected placement chains and audits every complete route. Chapters introduce two placements per group, three colored layers, and larger 37-cell hives. **1–3** selects queues; both scene and numbered cell buttons accept placement.
- **Potions (`potions.html`)**, inspired by [Magic Sort!](https://play.google.com/store/apps/details?id=com.grandgames.magicsort): select a source vial, then pour into another vial with the same top color or into an empty one. Each vial holds four doses; a pour transfers the maximal top run that fits. Finish with one full vial per color and empty reserves. Boards grow from three to six colors. Construction reverses only pours whose exact inverse is legal, then trims the audited route at its first solved state. **1–8** selects source/destination vials; invalid pours leave every drop in place.
- **Liaisons (`liaisons.html`)**, inspired by [Flow Free](https://play.google.com/store/apps/details?id=com.bigduckgames.flow): draw orthogonal paths between matching endpoints without crossing other paths or foreign endpoints. Connecting every pair is insufficient unless every cell is also covered. Grids grow from 4×4 with three pairs to 7×7 with six pairs. Randomized Hamiltonian backbite moves build varied full-grid routes, partitioned into colored paths. Mouse/touch strokes support backtracking and are one undoable action; sidebar cells and arrow keys offer alternative tracing. Hints explicitly clear conflicting strokes before suggesting verified complete paths.

Rule tests audit representative routes, color and tile conservation, maximal pours, blocked and crossing moves, full-grid completion, hint edits, corruption and exact replay. Browser tests exercise pointer and native touch input, keyboard tracing, complete games, reload, next levels, all chapter boundaries, and desktop/390px/320px layout checks.

## Nœuds and Gouttes

These two games have **48 distinct, deterministic, audited levels each**, for **96 puzzles**. They keep independent replay saves, optional sound, four chapter collections, undo, hints, restart and completion badges.

- **Nœuds (`noeuds.html`)**, inspired by [Twisted Tangle](https://play.google.com/store/apps/details?id=com.crescivegames.twistedtangle): drag rope attachments between free plots until no two taut cords cross, overlap or touch. Later chapters add more cords, larger gardens and fixed screw attachments. Plot occupancy and fixed anchors are enforced transactionally. The generator builds a separated arrangement, scrambles the movable pins, then audits a complete untangling route. Any crossing-free arrangement wins. Hints can move an occupied target's neighbor into a spare plot before placing the chosen attachment. Scene dragging, click-then-place and numbered sidebar controls all work. Each drag is one undoable move.
- **Gouttes (`gouttes.html`)**, inspired by [Happy Glass](https://play.google.com/store/apps/details?id=com.game5mobile.lineandwater): draw static ramps with the mouse or finger, then choose **Laisser couler** or press **E**. Sixty deterministic water particles fall under gravity, collide with the actual drawn segments and solid obstacles, and slide into the glass. Goals rise from 48 to 54 drops; expert routes reverse direction using two ramps. Every generated solution is audited using the same fixed-step particle simulation used for live play; an empty drawing is also checked to ensure the level needs a ramp. Strokes cannot cross obstacles, leave the drawing area or exceed the ink reserve. Collinear samples are simplified for smooth sliding. An alternative point editor supports drawing without dragging.

Gouttes animates the same deterministic simulation after committing a verified trial. Drawing is locked while water runs; undo cancels the animation and restores the exact pre-trial drawing. A failed trial can be saved, reloaded, undone or corrected without a life limit. Hidden tabs and open dialogs suspend the visible water simulation; reduced motion shows the result directly. Hints may clear a custom drawing before proposing the audited ramps and opening the tap. Rule tests audit all 96 levels, rope geometry, occupied/fixed plots, water conservation at every tick, actual fluid results, forbidden strokes, ink usage, failed trials, save replay and undo. Browser tests cover real mouse/touch dragging, hand-drawn water success, cancellation during a live stream, point-editor input, expert routes, collections and desktop/390px/320px layouts.

## Écluses, Dunes and Fringale

These three games provide **48 distinct, deterministic, audited levels each**, for **144 puzzles**. Every game has four chapters, independent local saves, exact undo, restart, optional sound, reduced-motion support and verified hints. Their names, illustrations and levels are original.

- **Écluses (`ecluses.html`)**, inspired by [Pull the Pin](https://play.google.com/store/apps/details?id=com.maroieqrwlk.unpin): remove permanent goupilles to drain balls through connected basins. Gray balls acquire color when mixed with colored balls. All ordinary balls must reach the basket intact and colored; premature outlets lose gray balls, and bomb routes destroy their neighbors. Later chapters add parallel feeders, a shared final basin and a tempting bomb opening. Mouse/touch pin picking, numbered sidebar buttons and **1–9** operate the openings. Invalid repeats leave the state intact; a destructive opening remains undoable.
- **Dunes (`dunes.html`)**, inspired by [Sand Blast](https://play.google.com/store/apps/details?id=com.inspiredsquare.sand.blast): choose a queue head and a drop column. Its blocks become grains that fall and slide diagonally around other grains and fixed stones. Any connected region of one color touching both tray edges clears entirely, including curved bands. Chapters add more bands, wider trays, shapes and central stones. Generation audits actual drops using the same fixed-step `SandFlow` simulation as the animation. Input locks during gravity, undo cancels it, and reduced motion resolves the drop immediately. **1–3**, arrow keys and **Space** provide keyboard placement.
- **Fringale (`fringale.html`)**, inspired by [All in Hole](https://play.google.com/store/apps/details?id=com.homagames.studio.allinhole): guide a hole under berries, fruit, cakes and flowerpots. Each swallowed object adds mass and increases the radius; an object must fit fully. Hedges enforce continuous collisions, and growth can prevent returning through narrow gates. Empty the small court before collecting larger food outside. Dragging records one undoable gesture; clicking an object seeks an actual route around walls, and arrow keys offer manual motion. Every level is replayed through real movement and growth, and hints verify a complete remaining tour or suggest undoing a blocked detour.

Rule tests replay representative routes, check deterministic distinctness, preserve balls/grains/food mass, audit live sand steps and rocks, reject malformed actions and saves, verify bomb/loss recovery, and enforce hole size, growth and wall collisions. Browser tests cover actual pointer and native touch play, keyboard alternatives, full first levels, exact reload/undo, animation cancellation, expert collections, navigation and 1440px/390px/320px layouts. Shared rendering, controls and original home previews live in `src/harvest-{canvas,config,style,previews}`; the three puzzle modules remain independent of the DOM.
